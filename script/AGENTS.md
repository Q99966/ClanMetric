# 临时脚本区工作约定

本文件适用于 `script/`，与项目根目录 `AGENTS.md` 一起读取。用户最新明确的脚本任务优先。

- 首批目标已明确为应急采集官方／ClashKing 联赛数据、保存包含 warTag 的完整战绩 JSON、生成成员排名信息与大本差详细核对两份结果和验证两源基本接口。采用手动单次运行，可重复补齐，支持 JSON 离线重算；支持当前届、指定 ClashKing 历史届及已有归档补采，不默认增加常驻自动采集。Windows 本地开发与离线验证，Azure VM 真实采集与接口测试。先读取 `doc/emergency-cwl-plan.md` 与 `doc/implementation-task.md`。本分支负责规划，实施由用户安排的另一位 agent 承担；实际执行范围从用户具体任务判断，不重复询问已有授权。
- 开始前读取本目录 `README.md`，明确目标、输入、环境、输出及验收标准。关键未知项向用户询问，可继续不依赖答案的工作。
- 具体脚本任务的实施集中在本目录；需要改动其他区域时先说明原因，并依据用户任务确认是否已在范围内。
- Python 使用 3.13 系列，复用项目已选框架的公开 API；不因临时验证另造通用调度、重试、ORM、迁移、日志或追踪框架。
- 仅配置当前验证需要的依赖；不自动搭建正式业务服务、创建业务表或部署服务器。
- 不将密钥、密码、授权头写入代码、报告或日志；不为了解文档而读取现有秘密配置文件。
- 保留可复现证据，明确实际验证范围和未验证内容；样本测试结论不能直接升级为普遍事实。
- 验证发现与已确认规则不同，应报告并交回规划讨论，不自行更改正式规则。旧测试代码以项目已确认规则校正。
- warTag 已发现与完整战绩已保存分别记录。官方保留窗口尚未确定，不写死联赛结束即失效，也不保证保存标签后一定能永久重新取得战绩。
- 启动按 `doc/menu-design.md`：YYYYMM 可选，无参数当前年月并提示，查不到不跨年月替换；只列 A～F，一次输入优先级，全降序，回车 A B D C F，不恢复旧导航或询问升降序。A 进攻总星数、B 进攻摧毁率累计、C 进攻大本差合计、D 总杯分、E 防住摧毁率累计、F 防御大本差合计。目标月全部联赛分别处理，共用同一次排序选择。
- 主流程官方有效且匹配目标就采用，含准备期／已结束；确认当前无目标联赛时打印“当前联赛并未进行，切换 ClashKing 渠道。”再切换。其他错误不能冒充未进行，明确年月不能被第三方另一月份替代。离线导出、补采与独立检查保留直接入口，排序序列可追溯与离线复现。
- 输出按 `doc/output-design.md`：JSON 在 script/data/，排名与大本差核对两份 CSV 在 script/results/，文件名统一按来源完整赛季标识日期年_月_日，结果另带排序代号，同届更新。第二份含成员名称、大本和逐轮列，每列注明进攻／防御全部差值，零值、无记录与缺失分别表示；不能将首场战争时间替换来源日期或猜测日为 01。
- 为确认整月所有届数，可查询第三方索引，即使官方当前一届有效也不能据此断言整月完整。每届优先有效匹配官方，备用补齐；月份枚举未核实与单届战绩缺失分别报告，不混用不同届。
