# 实施 agent 任务说明：应急联赛采集与导出

最后更新：2026-10-13。

本文供用户转发给脚本 agent。启动、排序、月内全部联赛、输出及来源策略已确认，覆盖早期操作菜单／文件命名方案；具体来源字段和真实配置需实施验证。本分支只创建文档，没有可执行脚本或真实采集。

## 1. 目标与范围

在 `script/` 实现 Python 3.13 应急工具，手动执行一次后退出，可以再次运行补齐已有归档。支持：

- 按部落查询当前届联赛。
- YYYYMM 主入口查询该月全部联赛，每届独立归档、排序与补分，使用本次同一排序选择，分别导出结果。
- 指定 ClashKing 返回的完整历史赛季标识查询。
- 根据已有 JSON 中的 warTag 补采对应联赛。
- 从完整战绩 JSON 离线生成排名信息、大本差核对两份 CSV，不请求外部接口。
- 分别验证官方与 ClashKing 的基本接口，并输出实际验证结果。
- 主入口可选固定 YYYYMM 参数，无参数当前年月并提示用法；只列 A～F，一次输入排序项及优先级，全降序，覆盖旧操作导航。

Windows 本地开发和离线验证，Azure VM 上真实采集与接口测试。每次只处理目标部落实际参加的战争，保留每场战争双方所需资料；轮数、人数、赛季标识与赛事时间采用实际数据。应急指定历史查询不修改正式平台首次绑定范围。

## 3. 实施组织

提供采集归档、离线 CSV 导出、官方接口检查、ClashKing 接口检查这四类可独立调用的能力。可以通过几个入口文件或同一入口的子命令组织，共享必要的数据源适配与计算函数；使用清楚的帮助文本和运行示例。

主启动按 `menu-design.md`：python ./XXX.py 202401／202412 指定年月，无参数当前年月并提示用法，查不到不改查其他年月。只列 A 进攻总星数、B 进攻摧毁率累计、C 进攻大本差合计、D 总杯分、E 防住摧毁率累计、F 防御大本差合计。输入 A B C 仅按这三项降序，最后按标签升序；回车默认 A B D C F。B／E 累计，不询问升降序或显示旧操作导航。

部落、完整赛季、归档及输出配置明确，不硬编码旧样本。官方有效且匹配目标就采用，含准备／已结束；确认当前无目标时打印“当前联赛并未进行，切换 ClashKing 渠道。”再切换，第三方仍查正确目标。鉴权、网络、限流等异常分别报告，不冒充未进行。目标月全部联赛分别归档、排名与补分，不混合，也不新增选一届菜单。

即使官方当前一届有效，也需发现该月其他联赛，可查询 ClashKing 赛季索引并验证来源身份；各届战争仍优先有效匹配的官方、备用补齐。月份枚举完整性与单届战绩完整性分开记录。无法核实整月覆盖时保存已取得数据并说明限制，不能宣称全月已采齐；某一届缺失不混入另一届的完整战绩。

完整历史标识查询、已有 JSON 补采、离线导出与两源基本检查仍通过独立入口或直接参数提供，不放回主操作导航。记录实际采用的排序代号与指标名称，离线导出可复现所选方案；两源检查分别执行，官方检查失败不能被第三方成功掩盖。非交互运行须有明确排序或确认后的默认行为，缺少必要输入时报错退出，不等待终端输入；--help 不请求 API。

使用 HTTPX 请求、所需的已选配置组件及 Tenacity 有限重试等公开能力，按需配置脚本专用环境和依赖版本。记录具体 HTTP 超时与重试参数、重试条件；鉴权／配置错误不盲目重试，来源限流要求等待时遵守。项目 API 缓存的 10 秒／60 秒预算不直接套用给这些外部请求。

手动脚本不需要调度器、业务数据库、Web 服务、SSE 或整套观测服务。正式业务代码、业务表、部署与主项目架构继续由主项目任务管理。

## 4. JSON 归档要求

主归档为 script/data/部落名称_部落标签_年_月_日.json，日期来自来源完整赛季标识；官方只给年月时需验证来源对应关系补足日期，不能填 01 或用首场战争 startTime 替代。有效标签和资料及时保全，身份未核实则明确待识别。完整身份匹配后按命名归档，同届更新，跨届不覆盖，详见 output-design.md。至少保留：

- 归档格式版本、目标部落、完整联赛标识与来源标识。
- 联赛资料、目标部落完整报名名单、轮次以及已发现 warTag 的对应关系。
- 每场目标战争的完整来源战绩、请求所用 warTag、双方成员与历史大本快照、全部实际攻击、战争状态与时间。
- 来源、采集时间、必要字段校验、缺失／待确认状态，以及计算采用哪个来源的依据。

先保存已发现 warTag 和联赛资料，随后每次取得目标战争战绩及时更新归档，不等全部战争请求或 CSV 计算成功。更新采用避免半写文件的方式，失败、中断或错误响应不能清空已保存的有效数据。

官方优先、第三方补齐，按已确认的必要校验与最终数据冲突规则处理。两源记录分别保留，不能互相冒充；目标归档所需的来源保留规则沿用项目文档，普通采集不无界保存所有中间变化。ClashKing 若展开整个分组，只归档目标战争详情并说明提取范围。

补采必须核对原归档身份；新一届联赛不能覆盖旧一届，重复运行不能重复累计攻击。当前届不可用时，不静默改查第三方最新旧赛季。未来尚未出现 warTag 的轮次提示后续手动补采。

## 5. CSV 要求

两份结果在 script/results/：部落名称_部落标签_年_月_日_排名信息_ABC.csv，以及部落名称_部落标签_年_月_日_大本差详细信息_ABC.csv。日期为来源完整赛季标识，例如 2024-12-02 对应 2024_12_02；ABC 为实际排序顺序，不能重排代号。

第一份延续成员整届汇总与所选规则排名；第二份为成员名称、大本和逐轮大本差核对表。按用户最新反馈，进攻和防御拆成两组列，先进攻轮次、后防御轮次；单条记录不重复显示合计，多条记录保留全部差值及合计，真实零值、无记录与缺失可区分；大本变动明确注明。特殊形式保持实际轮次，具体按 output-design.md，不额外恢复旧全逐轮明细文件。

两份结果能辨识联赛、数据时间、来源与完整性，缺失时排名留空或暂停；历史等级与差值能核对 JSON。同届更新，其他完整联赛不覆盖。

计算必须覆盖完整报名名单；使用战争当时的大本快照。进攻杯分单次四舍五入、.5 向上，再算防御杯分；每轮防御杯分取最低一次，其他防御指标累计全部实际记录。仅完整终局进行赛季防御补偿；排序按用户输入六项代号的顺序降序比较，不自动追加未选择的数值项。用户选中项全部相同的成员显示并列名次，采用竞赛排名（例如 `1、2、2、2、5`）；玩家标签升序只用于稳定排列并列成员，不拆分名次。

无实际次数的均值显示无值，整届无防御记录不套用其他成员均值。必要数据缺失时展示已有战绩与缺失状态，暂停排名和补分，不伪造未知为零。两份 CSV 从归档生成，在线导出与离线重算复用计算入口。

## 6. 验收与交付

离线验收至少验证：

1. 2 星、70% 对应进攻杯分 23、防御杯分 17；.5 的取整边界。
2. 同轮多次防御只有杯分取最低，次数、星数、摧毁率和大本差仍统计全部实际记录。
3. 四个有防御轮次合计 80 杯、整届七轮，补偿后 140；未出场也补，完全无防御无法估算。
4. 全报名名单含未出场成员、无值均值、所选序列的同分标签比较，以及进行中／缺失时不错误补分或恢复排名。
5. 途中失败后归档仍可解析，重复补采不重复累计、不跨届覆盖。
6. 离线导出不发外部请求，并与相同归档的在线导出结果一致。
7. YYYYMM 正确解析，无参数当前年月并提示用法；只有六项代号，A B C 只按其顺序降序，B／E 累计，C／D 正确。非法、重复及空输入按明确规则处理，非交互缺参不等待，排序可复现。
8. 官方准备／结束期有效且匹配仍采用；无目标显示指定切换提醒，其他错误不冒充未进行，ClashKing 查正确年月／完整联赛，同月多届不混用。
9. 输出目录与命名符合约定，排序后缀保留输入顺序，格式与扩展名一致；大本差核对表可逐轮核对全部记录、等级变化、零值及缺失，不误用最差防御杯分记录代表全部防御大本差。
10. 同月两届分别生成两份 JSON、四份 CSV，使用同一次排序输入而独立计算；官方当前一届可用时不遗漏月内其他已记录届，索引故障不会冒充全月采齐或跨届补分。

真实接口检查报告说明请求到达、字段解析、目标关联与数据完整性分别是否成立；记录实际验证时间、目标和原因。单个样本或 HTTP 200 不代表全部字段、全部历史联赛均可取得。

交付可执行脚本、帮助与 Windows／Ubuntu 运行示例、实际依赖版本、脱敏的归档示例、两份 CSV 示例、离线验收结果，以及真实接口验证记录或未运行的原因。运行所需部落／赛季和凭据从用户实际配置提供；缺少真实环境时继续完成离线工作，再询问缺少的运行条件，禁止在报告中编造成功。

首批不做内存／性能测量专项。凭据不得硬编码、回显、写入归档或报告。已确认决策不重复询问；来源身份、字段或执行条件存在关键未知项时向用户说明并提问。
