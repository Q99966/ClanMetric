# 应急脚本月份参数与六项排序输入

最后更新：2026-10-13。

启动约定已确认：YYYYMM 可选，无参数当前年月并提示；只列 A～F，一次输入优先级，全部降序，B／E 累计，回车 A B D C F。采集目标月全部联赛，每届独立处理；匹配有效的官方准备／结束数据均采用。旧操作导航已撤回，本文件没有待选启动方案。

## 1. 已确认的启动形式

~~~text
python ./XXX.py 202401
python ./XXX.py 202412
~~~

分别表示采集 2024 年 1 月、2024 年 12 月的联赛。XXX.py 是入口名称示意，实施 agent 需给出实际文件名。参数为六位 YYYYMM，年月必须合法，月份为 01～12；不再接受含糊的裸月份 12 作为新的标准入口。

~~~text
python ./XXX.py
~~~

不传参数时直接采集当前年月，并提示参数版用法，例如“可使用 python ./XXX.py 202412 查询指定年月”。查不到当前年月时明确提示，不自动退到上个月或去年。打印所用年月、当前年月判定所用时区和实际完整联赛标识，保持 Windows／VM 运行说明一致。显式 YYYYMM 不自动回退其他年或月份。

部落标签、凭据及输出位置通过已有配置或明确参数提供。主启动流程不再要求用户先选择操作、来源和一系列菜单；必要配置缺少时说明缺少的字段，不回显凭据。

## 2. 唯一的排序交互

启动显示以下六项及说明：

~~~text
请选择排名参考项，按优先级从高到低输入代号，统一降序：
A：进攻总星数
B：进攻百分比（摧毁率累计）
C：进攻大本差总和
D：总杯分
E：防住百分比（防住摧毁率累计）
F：防御大本差总和

例如输入 A B C：
先比较 A；A 相同才比较 B；A、B 都相同才比较 C。
直接回车：使用默认 A B D C F。
请输入排序代号：
~~~

- 输入的顺序就是实际排序优先级，列出的 A～F 顺序不自动成为排序方案。
- 用户可以选六项中的一项或多项，例如 A B C、D A B、A B D C F；没有选中的指标不额外加入比较。
- 所选指标全部按数值降序，不逐项询问升降序，不计算权重总分。
- 示例 A B C 即进攻总星数降序 → 进攻摧毁率累计降序 → 进攻大本差合计降序。
- 所选数值全部相同后，继续沿用玩家标签字符升序作最终稳定顺序。
- 读取一行空格分隔代号，大小写可以规范化；非法代号或重复代号提示重新输入，不静默删除、补加或重排用户选择。
- 空输入已确认采用原默认 A B D C F，即进攻星数 → 进攻摧毁率累计 → 总杯分 → 进攻大本差合计 → 防御大本差合计。E 展示为可选项，但不自动加入默认方案。
- 主提示只列上述六项。其他统计指标继续按规则计算与导出到 CSV，不自动扩大排序候选。
- 显示本次采用的代号序列与指标名称；目标月全部联赛使用同一次排序输入，逐届独立比较，不逐届重问。记录序列以便离线重现。

## 3. 六项的准确口径

| 代号 | 指标 | 已确认口径 |
|---|---|---|
| A | 进攻总星数 | 目标成员实际进攻获得的星数合计，不使用部落胜利奖励星数 |
| B | 进攻摧毁率累计 | 各次实际进攻摧毁率相加；已确认采用累计，不采用均值，可超过 100% |
| C | 进攻大本差合计 | 每次目标大本减成员自身大本，再求和；采用战争当时快照 |
| D | 总杯分 | 实际进攻杯分加适用阶段的防御杯分；完整终局时包含按正式规则计算的防御补分 |
| E | 防住摧毁率累计 | 每次实际防御的 100 减对手摧毁率，再求和；已确认采用累计，不采用均值，不对未被攻击或未出场轮次补此项 |
| F | 防御大本差合计 | 每次对手进攻者大本减成员自身大本，再求和；采用战争当时快照 |

杯分为平台分析分。进攻杯分、防御杯分及补分仍使用 doc/data-analysis-rules.md；本次改变的是脚本排序入口与所选优先级，不修改正式项目计算公式或 Web 排序配置。

## 4. 官方优先与切换提醒

主采集流程优先查询官方。只要官方返回有效且匹配目标联赛的数据就采用，包括准备期和已结束，不仅限于正在交战的阶段。确认当前无目标联赛时，打印提醒并切换 ClashKing 获取指定年月：

~~~text
当前联赛并未进行，切换 ClashKing 渠道。
~~~

- 只有已验证的正常“联赛未进行”情况使用该提醒；鉴权、配置、限流、网络与来源异常分别报告，不能全部解释成未进行。
- 指定月份不对应官方当前联赛时，第三方查询仍必须解析为用户选择的目标月份／完整联赛；说明官方当前联赛与目标不符，不伪称当前赛事一定未进行。
- 保存来源、实际采集的完整赛季标识及切换原因，不能把另一月份的战绩写入目标归档。
- 已确认准备期和已结束的有效官方数据继续采用；数据完整性与状态需校验，时间经过或有 HTTP 200 不单独代表完整。
- 未取得所需数据时，保存已有归档和缺失证据，暂停排名与补分，不因切换渠道伪造完整结果。

具体错误语义与字段读取依据接口规格及真实基本测试，不能根据一个 HTTP 状态码推断所有场景。

## 5. 历史、补采和离线能力

此前确认的完整历史赛季查询、已有 JSON 补采、离线导出，以及两源独立基本验证继续保留，通过单独入口或直接参数提供，不放回主脚本操作导航菜单。

YYYYMM 查询目标月全部联赛，不新增选一届的菜单。内部保留各届完整标识，按来源完整赛季日期年_月_日区分，各届独立归档、计算、排名与补分。同届更新，已有归档补采不把新届覆盖旧届，详见 output-design.md。

官方当前接口有效并不证明整月只有一届；为发现月内其他届及核对完整日期，可以查询 ClashKing 赛季索引，再对所需战争优先使用有效匹配的官方数据。官方不可取的战绩按既定备用策略补齐。月份枚举完整性与单届战绩完整性分别记录；索引不可用时保存已取得数据并说明整月覆盖尚未核实，不声称该月全部采集成功，也不将不同届的数据合并补洞。

参数与交互复用同一计算、排序及归档逻辑。非交互调用需提供明确排序序列或已确认的默认行为；不能在无人输入时挂起等待。--help 不请求 API。参数解析可继续复用 Python 3.13 argparse，简单代号输入使用标准库，无需新增 CLI 框架。[Python 3.13 argparse](https://docs.python.org/3.13/library/argparse.html)

## 6. 执行结果摘要

打印目标年月、发现的完整赛季列表、每届实际来源和数据完整性、所选排序、每个归档与 CSV 路径，以及缺失与待补采内容。没有目标月记录时明确提示，不改查其他月份。整月覆盖未核实和某一届战绩缺失分别说明；每届是否可排名／补分按其本身的数据判断。

## 7. 验收调整

实施 agent 验证：

1. python ./XXX.py 202401／202412 解析年月，非法长度／年月拒绝；无参数当前年月并提示，不跨年月替换；同月多届全部分别处理，用同一次排序。
2. 主提示只列 A～F，不显示旧操作导航；一次输入 A B C 实际只按 A、B、C 依次降序，C／D 的代号映射不可颠倒。
3. B 与 E 使用累计值；反向代号顺序改变优先级，未选择指标不介入比较，最终同分按标签。
4. 非法和重复代号反馈清楚；空输入采用 A B D C F，默认输出后缀为 ABDCF；手动 A B C 后缀 ABC，离线导出可复现。
5. 官方准备期／结束期有效且匹配的数据仍采用，确认无目标时显示指定提醒并切换第三方；其他错误不误报未进行，第三方仍查询正确年月与完整联赛。
6. 原有归档、补采、计算及数据缺失门槛不因启动方式调整而回退。
