# 应急联赛采集与 CSV 导出计划

最后更新：2026-10-13。

状态：应急用途、归档／结果、手动补采、Windows／VM 分工及启动方案已确认。YYYYMM 可选，无参数当前年月；六项一行降序，回车 A B D C F；采集目标月全部联赛独立导出。官方匹配有效均采用；完整赛季日期年_月_日命名，同届更新。本分支只规划，具体来源字段与真实环境由实施验证，见 [实施任务](implementation-task.md)。

## 1. 已明确的需求

- 应急获取 CoC 官方渠道或 ClashKing 的联赛数据，处理并生成对应 CSV。
- 将取得的基本信息保存为 JSON，尤其保留 warTag，降低对外部历史接口持续可用性的依赖。
- JSON 保存联赛资料、目标部落完整报名名单、warTag 对应关系及目标部落各场战争完整战绩，支持离线重新生成 CSV；不能只保存标签。
- 最新两份结果已确认 CSV／.csv：成员排名信息、大本差详细核对；第二份含成员名称、大本与常规七轮大本差，每轮列内同时注明进攻／防御。计算沿用正式规则，排序按所选代号序列；缺失时暂停排名与补分。
- JSON 自动保存在 script/data/，两份 CSV 在 script/results/，按部落与完整赛季标识日期统一年_月_日，结果另带排序后缀，同届更新，见 [输出约定](output-design.md)。
- 采用手动单次运行，可重复执行补齐已有归档；首批不提供常驻自动跟踪，不因重复运行创建调度服务。
- 支持按部落查询当前届、指定 ClashKing 返回的完整历史赛季标识查询，以及依据已有 JSON 的 warTag 补采；每次只处理目标部落参加的战争。
- 主 YYYYMM 入口采集该月全部联赛，每届独立归档、排名和补分，同一次六项排序输入用于全部届，不合并战绩。
- 提供官方与 ClashKing 的基本接口测试脚本。
- 首批不做内存与耗时测量专项；这些属于主项目后续的性能与资源验证。脚本自身的计算与文件输出仍需做功能验证。
- 本对话分支只负责脚本区域的计划、任务说明及验收；用户另行安排实施 agent。
- 运行分工为 Windows 本地开发与离线验证、Azure VM 真实采集与接口测试；脚本路径与参数需兼容两种系统。
- 启动可选固定 YYYYMM 参数，如 python ./XXX.py 202401／202412；无参数当前年月并提示用法。只显示 A～F，一次输入所选项与优先级，全部降序，B／E 累计，旧操作导航撤回，见 [年月与排序输入](menu-design.md)。
- 官方有效且匹配目标就采用，含准备／结束期；确认当前无目标时打印切换 ClashKing 提醒。年月身份、正常未进行及其他错误不能混淆。

项目既定规则参考 [分析规则](../../doc/data-analysis-rules.md)、[框架选型](../../doc/technology-selection.md)、[来源与存储](../../doc/data-storage-design.md)。临时脚本不另创一套排名算法。用户已为应急工具明确授权指定历史届查询；这不改变正式平台的首次绑定范围，也不意味着批量扫描全部历史。

## 3. 建议的任务拆分

建议使用以下职责拆分；具体入口文件名可以由实施 agent 在任务范围内确定：

| 任务 | 输入与工作 | 交付 |
|---|---|---|
| 应急采集与归档 | 明确的部落、联赛或已有 warTag；读取来源、校验关联、保存已取得信息及缺失状态 | JSON 归档、运行摘要与失败证据 |
| 结果生成 | 从已归档的完整战绩 JSON 计算，能离线重复生成 | 排名信息、大本差核对两份结果；格式按用户最终确认，附规则与完整性说明 |
| 官方基本验证 | 在可用环境验证鉴权、部落、联赛组及已发现战争的必要字段与关联 | 明确验证到哪一步的报告；正常无联赛与请求失败分别记录 |
| ClashKing 基本验证 | 对用户选定联赛验证可查询性、响应结构、报名名单及目标部落战争 | 覆盖情况与缺失报告，保留具体来源标识 |

采集与导出可以提供一个方便执行的入口；内部应允许在原始数据已保存后单独重新生成 CSV。基本接口验证可以共享所需 HTTP／配置能力，不能复制成多个算法版本或通用基础设施框架。

## 4. 应急数据保护建议

以下是实现已确认应急用途的接入建议，具体文件契约与更新方式继续细化：

1. 联赛组或备用资料取得后，先保存联赛标识、完整目标部落报名名单及各轮发现的 warTag，不等全部战争获取和 CSV 计算成功才保存。
2. 区分“已发现候选标签”“已确认属于目标部落”“已取得战绩”“已核验最终战绩”。联赛组含其他部落的候选 warTag 时，查询用于识别所属；归档的战争详情限定为目标部落参加的战争，并保留双方计算所需资料。
3. 每次成功取得目标战争的数据即更新 JSON；某场失败不能抹掉其他已保存数据。文件更新需避免中断后只剩半个 JSON，已有有效归档不能被错误响应或空结果覆盖。
4. 完整战绩 JSON 保留目标战争的来源字段、请求对应 warTag、采集时间、状态、名单和攻击记录，支持核验及离线重算。ClashKing 响应展开小组其他战争时，应提取目标战争，注明提取范围；不能称提取后的文件为整个 HTTP 响应原样备份。
5. 官方与第三方分别记录，使用项目已确认的官方优先与冲突处理规则。来源间战争或联赛对应关系无法验证时标为未确认，不能仅按月份或名称拼接。
6. 保存 warTag 不等于保存战绩；即使标签仍在，外部接口仍可能不可读。未取得完整战绩时明确标记归档缺失，不能承诺其已足够生成完整统计；已经完整保存的数据应可离线重算。
7. 未开始的占位标签与历史缺失分别记录；实际轮数、人数和赛事时间来自数据，不写死为七轮、月初或特定参战人数。
8. 指定历史届和补采已有归档时，核对部落、完整联赛标识及战争关联；不能因官方联赛组已切换为新一届而覆盖旧归档。明确指定月份不能静默改成其他月份；无月份时按确认后的最近月份规则解析，并打印实际目标。
9. 手动单次采集只保存当次已发现的信息。未来尚未出现的战争标签，需要用户后续再次运行才能发现；退出后不继续后台采集，报告应提示仍需补采的内容。

现有样本曾在战争结束后读取到官方战绩，精确保留窗口尚未验证。应急工具按及时保存设计，不能将“联赛结束即失效”作为已证实条件。已有证据见 [项目文档](../../doc/README.md#已有验证证据)。

## 5. CSV 与计算验收方向

最新两份 CSV 为排名信息、大本差详细核对，后者每轮同时注明进攻／防御；字段按 output-design.md 细化，计算满足正式规则，排序按六项代号约定执行：

- 按该届全部报名成员输出，不遗漏未出场或已离开成员。
- 单次进攻杯分四舍五入，恰好 .5 时向上进一，再计算防御杯分；不能沿用旧脚本向下取整。
- 每轮只有防御杯分取最低的一次；其他防御指标统计全部实际防御。
- 联赛完整结束后才补偿防御杯分，中间平均值保留精度，最终合计取整。
- 必要数据缺失时，保留已有战绩和缺失标记，暂停成员排名与补分；不把未知字段伪造成零。
- 实际次数为零时，相应均值显示“—”；不存在防御记录时按正式规则标记无法估算。排序仅按用户输入的 A～F 代号序列依次降序，B／E 为累计值，最后按玩家标签字符升序；输入 A B C 不额外插入杯分或其他未选指标。
- 文件可辨识来源、数据时间、联赛完整标识与计算版本；进行中结果不冒充完整终局排名。

少量离线样例需要验证取整、每轮最差防御、完整赛季补分、零实际记录、缺失和完整报名名单。至少包含已确认的 2 星／70% 对应进攻杯分 23、防御杯分 17 的例子，以及四轮防御合计 80、整届七轮最终防御杯分 140 的例子。这些是功能验收，不是性能测量专项。必须验证离线导出不发外部请求、途中失败后已有归档仍能解析、重复补采不产生重复攻击或跨届覆盖。

## 6. 可复用材料与接口证据

- [collect_cwl_analysis.py](../../../coctest/collect_cwl_analysis.py)：参考 ClashKing 请求及旧 CSV 格式；其取整、成员范围、防御杯分与缺失处理不能直接照搬。
- [validate_cwl_wartags.py](../../../coctest/validate_cwl_wartags.py)：参考战争标签验证及对齐字段；旧报告的汇总一致不能替代逐攻击与全报名名单校验。这两份旧资料位于项目根目录相邻的 `../coctest/`，未纳入本仓库；链接基准见 [路径约定](../../doc/path-conventions.md)。
- 旧采集脚本导出过概览、成员汇总、逐轮明细和战争记录四张表。本次最新要求为排名信息、大本差核对两份结果；完整逐轮战绩、战争关联与采集证据保存到 JSON 与验证报告。
- 2026-10-13 公开 [ClashKing OpenAPI](https://api.clashk.ing/openapi.json) 仍列出 legacy CWL season 接口；实施前按所用端点核对 schema，并用真实样本验证。规格存在不保证目标部落或目标历史联赛一定可取。
- [官方开发者文档](https://developer.clashofclans.com/#/documentation) 与现有官方测试脚本作为接口验证入口；尚未在本脚本区运行任何真实 API 请求。

依赖复用 HTTPX、所需配置与有限重试组件等已选能力，使用 Python 3.13；只配置当前任务实际需要的库。已确认手动运行，不需要引入调度器或安装整套 Web／数据库／观测服务。实际 HTTP 超时与短重试参数在脚本说明中明确，不能将主项目 API 缓存的 10 秒等待／60 秒执行预算直接当成脚本外部请求参数；脚本验证中的临时参数不自动成为正式服务选型决定。
